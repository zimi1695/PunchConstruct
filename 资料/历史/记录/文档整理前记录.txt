## 联机试作版

沿用游戏原生联机。所有玩家需使用相同游戏版本、BaseLib版本和本模组同一构建；无需Watcher。紧追不放的召唤标记按施加者独立结算，架势／古铜之拳的递增值和头盔触发状态加入保存与同步。

原生握手会拒绝游戏版本不同、缺少影响玩法的模组或模组版本号不同的连接，并显示版本／模组不匹配提示；本模组已声明影响玩法。相同版本号下自行替换文件的情况不保证能全部识别，联机仍应使用同一份文件。

当前0.4.15的26项功能验收及8项联机／恢复专项全部通过。2—4个独立游戏进程经原生ENet连接，九阶段状态一致；四人另测单程100±40毫秒、5%丢包及5秒断流。普通／强制断开、四人客端进程丢失、三人混组主机进程丢失后的重新组队读档均通过，倒序加入后身份、灼热铁斩波的精确强化次数／数值、附魔和四件工坊遗物一致。测试静音、使用隔离档，具体证据见[问题记录](资料/问题记录.txt)、tools/runtime/current-verification.json及qa-completion-0.4.15.json；0.4.14历史完整验收另保留在tools/runtime/qa/verification-0.4.14.json。发布候选0.4.15与该版验收一致，已私密上传，后续Steam验证因补美术暂停。0.4.16的选人动态另做定向验收，不沿用0.4.15全量结论。本机ENet热加入受原版开局关闭新连接限制；Steam邀请／Steam热重连、真实互联网线路和实际工坊订阅安装尚未实测，作者暂不能安排Steam双人实测。`TryPrototype.cmd`仍是关闭Steam接口的本地试玩入口。

## 本地使用

`launch.ps1`启动本地试玩，`launch.ps1 -PrepareOnly`只同步当前本地DLL／清单与资源，运行中的本地试玩会阻止同步。用户存档在`runtime/play-userdata`，不能清空或用测试档覆盖。`sync_runtime_art.py`令资源包与源码资产集合完全一致，避免旧包已删除资源残留；不写dist。0.4.15历史源码包含此前化学物X／宝箱过滤，以及开口扳手、自旋螺丝、备用指节、应急油壶，并加入灼热铁斩波／多次升级／斩波遗物兼容；发布候选已同步0.4.15并包含上述修改；旧0.4.11完整保留在runtime/qa/candidate-0.4.11。若试玩正在运行，退出后通过启动器同步，不能热替换。

仅编译：

```powershell
$env:DOTNET_CLI_HOME = Join-Path (Get-Location) '.dotnet-local'
dotnet build PunchConstruct/PunchConstruct.csproj -c Release --no-restore
```

`build.ps1`会同时调用打包；`package.py`、`release.py`也是发布工具，只有明确要求导出／发布时使用。日常整理、修复和验证不运行这些打包入口。

## 文档与素材

- `check_observer_art.py`：只读比对13张采用观者纹理与本机Watcher包的导入记录及真实纹理，`--record`仅更新现有来源表的路径核对记录。
- `check_documents.py`：只读核对82张牌的连续编号、名称／类型／品质统计、源码成员、素材来源／编号／导出覆盖、当前文档链接和关键规则，不启动游戏。
- `prepare_art.py`：按已采用素材导出纹理并更新素材清单。卡面和状态图标的审阅编号从主卡牌清单读取，轮廓图也计入清单，源图不改。
- `prepare_text.py`：由角色对白正文生成已接入对白；文件头的草稿状态不参与导出。
- `preview_icons.py`：根据状态图标清单生成全部已采用图标总览。
- `Inspect`与`game-reference`：本地游戏接口、IL和原版资料。游戏参考与历史资料不是当前角色设定。

## 定向验证

统一入口：`python tools/check_current.py 模式`。使用独立临时副本和测试存档，结束后清除副本，仅保留`runtime`对应日志。一般仅加载BaseLib与本模组；modes另加载临时QaExitProbe，在133项原生种子／挑战检查结束后释放离开场景树的闲置卡牌缓存，等待渲染帧再退出，不改测试内容或正常游戏。该QA程序集及指纹登记在日志和结果中，不装入候选／试玩。通过判定同时检查成功标记、失败标记、退出码及未分类错误，PASS之后的资源／脚本错误同样判失败。已在BaseLib单独启动中复现的精确底层诊断形式，以及调试房间未自动保存时原版清理两个不存在临时存档文件的提示，会单独分类；其他异常不放行。

单人专项的新归档同时保留DLL／PCK／清单的SHA256、临时QA助手指纹及原始游戏日志；`result.json`的`build`记录实际测试文件。`persist`与`observerpersist`的写档和续玩日志分别保留在同一个证据目录，避免只留下第二次启动的记录。历史归档保持原样，不能因工具补充了字段而视作已经重测。

## 日志与自动测试约定

后续自动测试一律静音：临时测试档的总音量、音乐、音效和环境音均为0，显式游戏测试入口另设置主音量为0。此设置仅用于隔离测试档，不修改作者正常试玩音量；音效专项仍可检查事件是否调用。

单人与联机共用JSONL诊断结构。正常试玩日志位于`runtime/play-userdata/PunchConstructTest/PunchConstruct/logs`，原生完整日志仍是`runtime/play.log`；实际日志目录会在启动时以`[PunchConstruct LOG]`输出。Steam环境使用对应游戏用户目录下的`PunchConstruct/logs`，不写入模组安装目录。

每条记录包含schema、UTC时间、递增序号、进程会话、局次、级别、事件名、当前上下文和数据。启动记录包含DLL指纹、模组／BaseLib版本；开局记录包含种子、挑战参数和玩家槽位／角色。行动使用原生actionId，选牌使用choiceId；不同机器应以同种子、房间、行动／选择编号和玩家槽位对照，不使用各进程不同的session字段匹配。

记录房间、战斗、回合、行动开始／完成／耗时、等待选牌、发出／收到选择、退出、断开和状态分歧；行动异常、房间异常保留异常类型、信息和堆栈，分歧附玩家状态摘要。原生警告／错误另标为native.message，不能仅据此认定是本模组造成。玩家使用槽位，原生消息使用游戏自带Steam ID清理，不主动记录昵称、账号、聊天或网络地址；日志只保存在本机，不自动上传。

日志每份约2MiB轮转，最多保留12份；重复的相同原生警告／错误在5秒内合并并记录压制数量，最多缓存128种消息。轮转和写入异常不会中断游戏；无法写入时只提示一次，并保留原生游戏日志。日志不加入存档、状态校验或网络消息，不消费游戏随机数。

`python tools/diagnose.py`只读汇总正常试玩日志；`python tools/diagnose.py 路径 --events`查看完整时间线，也可用`--session`限定某个进程。联机排错保留所有玩家同一次运行的日志和原生日志。测试原始日志及结果按时间分别留在`runtime/qa/场景-时间/`，含构建指纹与日志SHA256；失败和中止也保留证据，不覆盖成通过。旧平铺日志仅为最近一次便捷副本。

## 联机定向验证

当前本地源码、试玩及已验收候选均为0.4.15。以下命令检查两人组合、三人混组和四人构装体，也支持`--package-dir`只读测试现有候选的三个文件：

```powershell
python tools/check_coop.py --guest construct
python tools/check_coop.py --guest necrobinder
python tools/check_coop.py --guest ironclad
python tools/check_coop.py --guest necrobinder --players 3
python tools/check_coop.py --guest construct --players 4
python tools/check_coop.py --guest construct --latency-ms 70 --jitter-ms 20 --loss-percent 2 --blackout-seconds 3
python tools/check_coop.py --guest necrobinder --players 3 --latency-ms 90 --jitter-ms 30 --loss-percent 3 --blackout-seconds 4
python tools/check_coop.py --guest construct --players 4 --latency-ms 100 --jitter-ms 40 --loss-percent 5 --blackout-seconds 5
```

每次启动2—4个独立游戏进程，使用原生ENet连接、原生大厅及真实网络行动／选牌消息。默认实际渲染、静音；不关闭原生状态校验。临时文件只协调测试布置和比较结果，不传输玩家选择。直接进入测试战斗与事件，不自动打完整局。仅结束该脚本自己启动的进程，用户存档和Steam游戏文件不变，不更新dist。

弱网参数启用仅绑定127.0.0.1的独立UDP代理，各客端经过独立端口与主机通信。latency是单程延迟，jitter是每个数据报的随机偏移，loss是双向随机丢包百分比；代理随机数独立于游戏随机数。blackout会在第一张愈战愈勇的真实手牌选择前丢弃双向数据报，持续指定秒数后恢复，不传递或伪造游戏选择。结果记录各方向实际收发、丢包、断流计数、延迟和阶段事件；必须确实发生丢包／断流并且全部端断言、原生状态校验和九阶段快照通过才算成功。每轮上限300秒。

Windows可能在原生主机正常退出后向UDP代理报告端口关闭；只有所有端均已完成最后checked屏障时才作为退出事件保留。提前发生则仍判失败，游戏错误判定不变。网络压力结果以独立-network键写入current-verification.json，不覆盖普通直连证据；若已有当前构建的网络压力失败，汇总也会列为失败。历史失败结果始终保留在自己的qa目录。

以上2／3／4人弱网配置已在0.4.10通过，各组九阶段快照全部一致。断流结束后的恢复是同一连接上的短时断流恢复，不是掉线后重新加入；不据此宣称已验证Steam或热重连。实际数据报计数和对应目录见问题记录。

测试覆盖独立召唤标记、遗物成长和归属、回合结束、普通／升级生成牌、延迟随机伤害、真实手牌变牌选择、战斗结束重置及海玻璃远端奖励选择；另检查连续战斗、各玩家同时提交攻击、队友死亡后的胜利与开口扳手归属；0.4.13另核对新螺丝的独立伤害标记／下回合抽牌、油壶同步目标随机数及指节击败格挡。比较战斗开始、标记、神格、下一回合、临时力量消退、变牌、奖励、并发行动、幸存者胜利九个阶段的所有进程快照。0.4.14另让每位玩家通过原生网络队列打出强化三次的灼热铁斩波，核对11伤害／11格挡；快照包含精确强化次数和动态数值。未知错误、诊断观察器异常、异常退出、缺失快照或任一快照不同均判失败。

`runtime/coop-verification.json`保留0.4.1汇总，随后构建的证据也保留在`runtime/qa`。最新专项汇总见`runtime/current-verification.json`，版本、DLL指纹及覆盖以文件内记录为准，不能把旧汇总视为新版全量验收。0.4.15历史验收资源为158份，包括灼热铁斩波、新遗物、黄铜螺帽图标及大图、隐藏能力的透明纹理、神格光束原图集及4份蜈蚣局部兼容资源。图标更新使用icons／focus定向检查。汇总必须同时具备26项功能、2／3／4人直连、四人弱网和四项断线恢复的成功证据，才标记full_local_verification；missing_multiplayer和missing_recovery列出缺项。

这组本机测试不证明Steam邀请、真实互联网线路、Steam热重连或其他模组组合。`launch.ps1`是关闭Steam接口的本地试玩入口。发布候选保留0.4.15，本地工作区试玩已更新0.4.19；联机证据与适用构建见[问题记录](../资料/问题记录.txt)。

## 联机断开与存档恢复

`RecoveryProbe`是独立QA模组，仅复制进临时环境，不能装入试玩或发布目录。支持2—4人，两阶段各启动全新游戏进程：先建立原生联机、准备升级／附魔牌和专属遗物并等待主机存档落盘；一名客端退出后，其余客端检查连接与对局仍保留，再由新进程实际加载主机磁盘存档、经原生LoadRunLobby重新组队，核对状态并实际网络出牌。每阶段上限150秒，静音、独立档，不推进整局。

```powershell
dotnet build tools/RecoveryProbe/RecoveryProbe.csproj -c Release
python tools/check_recovery.py
python tools/check_recovery.py --players 3 --party mixed
python tools/check_recovery.py --players 4
python tools/check_recovery.py --players 3 --party mixed --resume-order reverse
python tools/check_recovery.py --abrupt
python tools/check_recovery.py --kill-client --players 4 --resume-order reverse --package-dir dist/SteamWorkshop/content
python tools/check_recovery.py --kill-host --players 3 --party mixed --resume-order reverse --package-dir dist/SteamWorkshop/content
dotnet build tools/RecoveryProbe/RecoveryProbe.csproj -c Release -p:NativeOnly=true
python tools/check_recovery.py --independent --abrupt
```

`--party mixed`使用构装体主机、亡灵契约师客端和铁甲战士客端；其他配置为全构装体。构装体各槽位设置不同数量的测试牌和不同层数的附魔，避免同牌组掩盖身份互换。`--resume-order reverse`只在读档时倒转客端实际加入顺序，玩家网络身份保持原值；快照仍须逐玩家与保存前完全一致。该参数不伪造或改写原生身份分配。

历史0.4.14的26项功能和8项联机／恢复已全部通过，使用该版本地试玩的实际三文件，未重新导出候选。RecoveryProbe为各构装体另准备不同强化次数的灼热铁斩波与开口扳手／自旋螺丝／备用指节／应急油壶，快照包含CurrentUpgradeLevel及全部动态数值；正常与强制断开、四人客端丢失／三人混组主机丢失后的倒序回组都核对逐玩家身份及物品。恢复四项分别45／45／123／50项，目录及QA助手指纹见问题记录。此QA助手仅放临时测试环境。

0.4.10补充三人混组40项、四构装体88项、三人倒序回组40项通过；全部保存前／恢复后快照一致。各组合与顺序以独立键保存到current-verification.json，保留原双人结果；具体目录及QA构建指纹见问题记录。没有改变游戏DLL或重新导出候选。

0.4.10普通退出／续玩30项通过，强制关闭时原生MapDrawingModeChangedMessage报错的严格失败及独立对照均保留。0.4.11仅对包含构装体的对局补地图断开清理和ENet终止peer的原生通知，强制关闭／恢复首轮37项通过。恢复前先实际同步地图绘图模式，断开后再核对本地模式已复位，防止将整个绘图功能禁用来消除报错。

`--kill-client`／`--kill-host`由脚本直接终止自己启动的对应隔离进程，不调用正常退出；存活端必须由真实原生断开通知／菜单状态完成断言，再用全新进程组队读主机磁盘存档。被故意终止的一端标记expected_termination，不冒充执行过退出后断言。文件只补齐已终止进程的QA屏障，不能满足存活端的原生断开条件；不修改游戏超时参数。两参数与--abrupt互斥。

`--native-control`仅更换原版角色但仍加载角色模组；`--independent`使用不引用角色程序集的NativeOnly产物，移除角色模组并在各进程检查程序集缺席。两种对照不能混称。NativeOnly的输出在bin/Native下，与普通QA产物分开。

本机原生ENet开局调用SetHostIsClosed(true)，会拒绝运行中新连接。`--live-join`仅用于保留原版加入界面的诊断，实际超时不能算热重连通过。没有为测试打开原生关闭的端口。Steam线路仍须单独验证。报告中的recovery_checks保存本角色退出／强制关闭／进程丢失恢复结果，diagnostic_controls保存热加入和原版／独立对照，失败保持失败；所有快照、原始日志和隔离存档留在qa独立目录。

## 获取与结算规则

- 永久牌组拥有某组任意成员后，该组卡牌权重×2；重复成员和跨组不叠乘。移除最后一张成员后取消加权。具体前提见卡牌清单，加权不解除前提。
- 色彩哲学家使用本角色选入的储君、亡灵契约师、机器人卡牌，包含对应六张体系原创：共36种，分别15／11／10。三次各3选1、不分品质，三次合计9张候选全部不重复；豁免小组前提、加权和外来角色解锁限制，不含先古卡及其他归属的原创牌。
- 海玻璃仍从三系原版搬运子集（共30种，12／8／10）各展示5张，共15张，任意选取；每色内部不重复，不限品质。当前实现同样豁免小组前提、加权和外来角色解锁限制，保证每色候选数量。
- 商店压制、流星雨、守护者、吹哨使用先古卡渠道；守护者另有牌组前提。拳王形态只走尘封魔典，古老牙齿将铁斩波替换为灼热铁斩波并强化三次。吹哨保留原先古之民渠道。
- 普通随机奖励、商店、战斗生成及随机变化均检查本角色卡池成员。明确指定的事件专属牌、诅咒／状态／任务牌、小刀、君王之剑等固定衍生牌保留原机制。
- 未明确改动的机制沿用原版。卡牌描述顺序就是结算顺序；灾厄免伤条件为大于等于生命值。
- 铁斩波形态逐段计次，只按未格挡伤害获得格挡，叠加增加可触发次数。
- 卸甲成军强制将本回合新获得的格挡替换为等量召唤，已有格挡保留，格挡修正只计算一次。

- 紧追不放改为角色造成5（升级6）点伤害，再为目标附加本回合的召唤标记；角色及自己的奥斯提击中该目标时，每段召唤3（升级4），不要求奥斯提已存在或先攻击。取消护卫发牌前提，保留召唤组加权。其余角色仍用原版。

拳击构装体 0.4.15 安装说明（Windows电脑版）

你需要已经在Steam安装好《杀戮尖塔2》。安装前先退出游戏，Steam保持打开。

发给朋友哪些东西？

把本说明旁边的content文件夹和这份安装说明一起发给朋友。
朋友把收到的文件保存到桌面；如果收到的是压缩包，先右键选择“全部解压缩”。
打开content文件夹，里面应有这三个文件：

PunchConstruct.dll
PunchConstruct.pck
PunchConstruct.json

后面要用的是这三个文件，先记住它们的位置。

第一步：订阅BaseLib

BaseLib是本角色必需的基础组件，安装一次即可。

1. 复制下面的网址，到浏览器地址栏粘贴并按回车：
   https://steamcommunity.com/sharedfiles/filedetails/?id=3737335127
2. 确认页面名称是BaseLib，作者是Alchyr。
3. 点击绿色的“订阅”按钮；如果网页要求登录，先登录自己的Steam账号。
4. 回到Steam，等下载任务完成。

已经订阅过BaseLib的人，等Steam下载完成后继续第二步。

第二步：让Steam帮你找到游戏文件夹

1. 打开Steam，点击上方的“库”。
2. 在左边的游戏列表里找到《杀戮尖塔2》。
3. 鼠标右键点击游戏名，选择“管理”→“浏览本地文件”。
4. Steam会自动打开你的游戏安装文件夹。这里能看到SlayTheSpire2游戏程序。

这个文件夹可能在C盘，也可能在D盘，以Steam刚打开的位置为准。

第三步：建好两个文件夹

在刚打开的游戏文件夹里操作：

1. 找到名叫mods的文件夹并打开。
   如果没有：在空白处点鼠标右键→“新建”→“文件夹”，把名字改成mods，再双击打开。
2. 在mods里面，再新建一个文件夹，名字改成PunchConstruct。
3. 双击打开PunchConstruct文件夹，先让这个窗口保持打开。

第四步：复制三个文件

1. 打开之前收到的content文件夹。
2. 按键盘Ctrl+A，选中里面的三个文件。
3. 按Ctrl+C复制。
4. 回到刚建好的PunchConstruct文件夹，按Ctrl+V粘贴。

完成后，摆放位置应该是这样：

游戏文件夹（能看到SlayTheSpire2游戏程序）
└─ mods
   └─ PunchConstruct
      ├─ PunchConstruct.dll
      ├─ PunchConstruct.pck
      └─ PunchConstruct.json

检查一下：打开PunchConstruct文件夹，直接就能看到这三个文件。
这些文件只需要复制，不需要双击运行。

第五步：启动并启用模组

1. 回到Steam游戏库，点击《杀戮尖塔2》的“开始游戏”。
2. 如果首次弹出“是否要加载模组？”，选择“加载模组”。
3. 按提示退出游戏，再从Steam启动一次。
4. 在游戏设置里的“模组”页面，确认BaseLib和拳击构装体已启用；如果修改了开关，按提示重启游戏。
5. 进入新游戏的角色选择界面，能看到“拳击构装体”，就说明安装成功了。到这里即可，不用马上开局。

准备和朋友联机时

两个人都按上面的方法安装，都从Steam启动游戏，并互加Steam好友。
本次核对组合是：游戏0.111.0、BaseLib 3.4.7、拳击构装体0.4.15；双方版本和启用的其他模组也要一致。
工作区里的TryPrototype.cmd用于离线试玩，Steam邀请测试要使用Steam的“开始游戏”。

遇到问题时

找不到mods：按第三步自己新建。
列表里没有拳击构装体：先按上面的摆放示意检查三个文件的位置，再完全退出游戏并重新启动。
提示缺少BaseLib：回到第一步检查订阅和下载，在游戏里确认它已启用。
提示版本或模组不匹配、启动报错：把提示原文和双方游戏／模组版本告诉作者，再一起处理。

本候选尚未上架创意工坊；Steam邀请和热重连仍待实际双人测试。

拳击构装体：本质铁斩波

[h1]拳击构装体[/h1]
尖塔的本质，是一个巨大的铁斩波。
解锁可用角色：拳击构装体，带着全尖塔攻防一体的艺术品，打倒一切

[h2]模组内容[/h2]
来自暗港「重拳出击」的拳击构装体，成为可用角色。

75种卡牌，包含围绕“有攻有防”选入的各角色卡牌、11张原创设计，以及特殊渠道获取的先古卡牌。锻造、召唤、灾厄等体系有了新的搭配，同体系卡牌也更容易凑齐。

加入角色专属遗物，并为部分原版遗物调整效果、外观与获取机会，让它们更贴合拳击构装体。相关调整仅对本角色生效。

包含9位先古的27组专属对白，以及「重拳出击」中与同类相遇的特殊文本。

[h2]安装与版本[/h2]
需要 BaseLib（已验证3.4.7）。订阅后在游戏模组管理中启用。
当前为试玩版本，已验证Windows、游戏0.111.0、中文。本地2—4人联机已做定向验证；Steam邀请、Steam热重连及其他版本和系统尚未验证。

[h2]制作与素材来源[/h2]
设计与制作：铁斩波。部分原创美术采用AI辅助生成。
《杀戮尖塔》系列的原版角色、卡牌与素材归Mega Crit所有。选入的观者卡面及状态图标取用自Boninall的“观者 Watcher”模组（0.10.3）：[url=https://steamcommunity.com/sharedfiles/filedetails/?id=3747526116]原模组页面[/url]。
本模组为免费、非官方社区作品，与Mega Crit无隶属关系。

本轮修复

1. 变牌音效：愈战愈勇原先在确认选牌后、变牌动画开始前播放。现在由原生闪光动画实际更新卡面时触发一次；不依赖固定延迟，取消／中断而未出现卡面替换时不额外播放。本地与远端分开处理。
2. 潘多拉魔盒：原版只识别打击／防御，遗漏小斩波。现在仅在本角色中额外识别可变化且可移除的小斩波，沿用原生批量变化、随机数、结果预览及原有打击／防御规则。初始通常变化5张；永恒小斩波保留；铁斩波、东尼斩波、震荡不误变；结果仍受本角色卡池与固定渠道限制。其他角色保持原版。已在旧版本领取过的魔盒不自动重放拾取效果。
3. 出拳拖沓：此前误按选人声处理，现按作者纠正处理战斗出拳。保留原版录音及音高，单拳0.38秒、双拳0.65秒主体后淡出0.06秒；每个角色独立控制，再出拳停止自己的上一拳余音，离开场景释放。动画循环、伤害段数、原有命中等待、防御声音不改。原生受控声音失效时记录日志并退回原生播放，不阻塞卡牌。
4. 选人声质感：旧简易合成稿已归档，重做为低沉拳套接触、碰击与干燥机械卡扣，仍0.32秒。是否合乎作者听感仍由试玩反馈判断；不把程序验证等同于听感认可。
